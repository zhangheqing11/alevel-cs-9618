## 3. 首学一个 P4 题型

1. **读卡**：`rows.py card P4-XX-NN`——考法、识别信号、解题思路、Python 模板、得分表述、得分点地图、易错、代表题精讲、对应练习、下一道变式。
2. **代表题精讲**（直接讲，不先让学生做）：
   1. 出处与题型：题号、分值、MS 点数与 Max；打开 QP 原页（`rows.py render`）与 MS（`rows.py get --ms`；MS 的 Python 范例丢了缩进，要看 `render --ms` 原页）。
   2. **读规格**：把题干逐条列成清单——模块名与参数、返回什么（return / print / 写文件）、全局还是局部、数组大小与初值、指针指向（首项、末项还是下一空位）、文件名与每行格式、提示与输出格式。告诉学生：MS 的得分点几乎一一对应这些要求。
   3. 设计：structured English → 选循环与数据结构 → 边界（空 / 满、找不到、文件不存在、最后一行无换行）。
   4. 完整程序：卡里给的是整道大题的可运行程序；讲本小问那几行时在注释里标得分点号（`# MP3`）。需要时你在 `work/tmp/` 里运行它展示输出（不写进 `attempts/`）。
   5. MS 逐点对齐：表格列出该小问每个得分点的 MS 原文、对应的行、技能标签；P4 的 MS 并列三种语言，得分点与语言无关。
   6. 证据格怎么交：哪几格贴代码、截图格要看见什么。
   7. 易错：卡片「易错与失分」+ 该题考官报告摘录（展示为「考官报告指出 …」）+ 有范答的卷（s21_42 ECR、s24_42 Example Responses）展示相关段落。
   8. 迁移：换指针约定、换文件格式、函数改过程、加一个条件，各自影响哪几行。
3. **变式与练习**：
   1. 变式 = 卡片「下一道变式」那一行（括号备注只给自己看）；`rows.py ex "<行 id>"` 找到它的练习文件夹（就是那道大题）。
   2. 你运行 `make try EX=practice/p4/<卷>_q<题号>`：它创建 `attempts/practice/p4/<卷>_q<题号>/solution.py`（starter 只有分节注释与主程序入口，声明与模块头要学生自己写——它们本身就是得分点），并把 `files/` 里的数据文件复制到旁边。
   3. 告诉学生：
      - 看题：优先看你渲染的 QP 原页（考场原样），或 `task.md` 的导读、英文原题、Python 接口（各练习标题写法略有不同）；「证据文档对照表」「人工核对清单」以及讲 QP / MS 差异、得分点编号、原页核验的节有 MS 得分点和范例缺陷，写完、测完再看。
      - **作答范围**：变式那一小问，加上它依赖的前面小问（声明、类、被调用的模块）；其余小问可以先空着。题目要求的标识符、文件名、初值一律照抄。
      - 主程序写在 `if __name__ == "__main__":` 下；提示语写在 `input("…")` 里（D13）。
      - 可以随时自己测：在作答文件夹里 `python3 solution.py`，或 `make try EX=… K="…"`（§4）。考场上也能运行，所以自测调试是允许的；写完说「测一下」。
4. **「测一下」**（批改顺序）：
   1. 跑测试：`make try EX=… K="<本型那几行的测试名 + 它依赖的前置测试>"`。本型的行 = `rows.py find --paper <卷>` 里这道大题中主题型是本型的那几行；它们的测试名取自 task.md「证据文档对照表」。用中文解读：失败的测试名、docstring 里的行 id 与得分点、输入 / 期望 / 实际、traceback 的最后一行（programming.md §9）。不直接给修正代码，按提示阶梯走。
   2. 人工核对：对照表「人工核对」列与「人工核对清单」里属于这几行的条目，逐条看代码（§5）。
   3. MS 对齐：`rows.py get "<行 id>" --ms`，得分点表「MP | MS 原文 | 学生代码 | 结果 | 技能」，按 Max 封顶。测试通过不等于得分点齐，测试失败也不一定丢分点——两边分别判（SKILL.md §6 的 P4 门槛要两边都过）。
   4. 截图格（若在范围内）：按 §5 核对输出内容。
   5. 该题若在 §6 的 MS 缺陷清单里，说明「照 MS 得分点给分，自己的程序按正确写法」。
   6. 判定并写记录表（§8）。
5. **整题**：一章学完，或一道大题涉及的题型都学过以后，把这道大题完整限时做一遍（按分值 × 2 分钟），`make try EX=…` 不带 K 全跑，并按对照表把所有证据格过一遍。整题是 P4 最接近考场的练习，章末复测优先用它。

## 4. 用 K 只跑一部分测试

- 测试名大多以小问号开头（`test_1b_…`、`test_3bi_…`），但**不总是**：例如 `practice/p4/9618_w22_42_q3` 的 3(c) 由 `test_3e_ii_screenshot_total` 和 `test_3c_…` 共同覆盖。每次都从 task.md「证据文档对照表」的「自动测」列取测试名。
- `-k` 是子串匹配：`K=3bi` 会同时选中 `3bii`、`3biii`；要精确就写 `K=test_3bi_`。
- 多个用 `or`，整体加引号：`make try EX=practice/p4/9618_w22_42_q3 K="3a or 3b"`。前面小问的测试（声明、构造方法）通常要一起跑，后面的小问依赖它们。
- 结果读法：`passed` / `failed` / `deselected`（被 K 排除）；`skipped` 表示没找到 `solution.py`；`AttributeError: module … has no attribute 'Enqueue'` 表示还没写或名字没照抄；`test_…_no_algorithm_shortcuts` 一类测试失败，表示用了 `sort()`、`in`、`index()` 等代劳题目要求的算法（D10 ③）。

## 5. 证据格与人工核对

`task.md`「证据文档对照表」一格一行：证据格 → 行 id → 分值 → 交代码还是截图 → 自动测（测试名 · 得分点）→ 人工核对（得分点）。表下的「自动占比」只是验证覆盖口径，不是考试分数。

**常见人工核对项**（每条都要对回该行 MS 的原文）：

| 项 | 看什么 |
|:--|:--|
| 模块头 | `def` 名称与参数个数、顺序照题目；MS 的「header (and end where appropriate)」在 Python 里就是 `def` 行与缩进块 |
| 声明 | 数组是真实 list、大小与初值对，并有英文注释写类型与大小（`Queue = [-1] * 50  # INTEGER, 50 elements`）；类的属性在 `__init__` 里初始化并注释类型；只写注释或空 list 不给声明分（D10 ①） |
| 作用域 | 全局变量在模块顶层；函数里给全局变量赋值要 `global`；题目说「局部于主程序」就不要放顶层 |
| 指定算法 | 写冒泡就有比较与交换；写递归就有递归调用与基本情况；不用 `sort()`、`sorted()`、`index()`、`count()`、`max()`、成员测试 `in` 代劳（D10 ③）。`for i in range(…)` 的 in 是循环语法，不算 |
| 文件与异常 | 打开模式对；**所有**文件访问都在 `try` 里；`except` 有合适输出；关闭位置合适（`with` 也可） |
| 指针约定 | 照题目给的初值与指向（D10 ②）；不靠 Python 负下标掩盖错误 |
| 给定伪代码 | 补全或翻译题照原伪代码结构，没有多余功能（「must match structure of given algorithm」） |
| 截图格 | 截图里有 MS 要求看到的输入与输出（含无效输入被拒的过程、要求同屏可见的文件名）；不能用最后一次运行覆盖之前要求的测试 |

**截图怎样核对**：学习时由你按 QP 给的测试数据运行学生程序，把控制台输出当作「截图」对照 MS 对该格的描述：

```bash
~/.venvs/alevel-cs/bin/python -c "import sys; sys.path.insert(0, 'tools'); from testkit import run_script; r = run_script('attempts/practice/p4/9618_w22_42_q3/solution.py', stdin='', files_dir='practice/p4/9618_w22_42_q3/files'); print(r.stdout); print(r.stderr)"
```

`stdin` 按 QP 的测试数据与顺序写，每个输入后跟 `\n`。学生也可以在作答文件夹里 `python3 solution.py` 运行后把输出贴过来。

## 7. P4 Python 写法要点（批改与示范都按这个）

1. **标识符照抄题目**：过程 / 函数 / 类 / 属性 / 全局变量名与文件名完全一致（`ReadWords`、`WordArray`、`QueueData.txt`），哪怕 Python 惯例是 snake_case。测试按这些名字调用。
2. **声明**：Python 没有声明语句。MS 的 Python 示例用「初始化 + 类型注释」体现声明（`self.__Data = PData  # INTEGER`），所有属性在 `__init__` 里初始化，全局变量在模块顶层初始化；数组要真的建出来并注释大小与类型（D10 ①）。二维数组每行独立创建（`[[0] * 4 for _ in range(3)]`），对象数组每个元素独立创建。
3. **OOP**：属性按题目要求私有（`self.__Name`）；构造器 `__init__`；getter / setter 照题目命名（`GetData()`、`SetData()`）；继承 `class B(A):` 并调用 `super().__init__(…)`；多态 = 子类重写方法；包含 = 容器类的属性是对象数组。
4. **ADT**：题目规定用数组 + 指针实现栈、队列、链表、二叉树时，就用固定大小的 list 和整数指针（空指针按题目约定，常为 −1），不换成 Python 内置结构——得分点检查的正是指针更新。题目给了指针初值就照题目用（D10 ②）。
5. **算法**：要求实现冒泡 / 插入排序、二分查找、递归时，写出算法本身（D10 ③）。
6. **文件与异常**：按题目用 `try` / `except` 包住全部文件访问与类型转换，输出提示；读到的行先去换行符（`.strip()`）再转换；`write()` 不自动加换行；`"w"` 覆盖、`"a"` 追加。
7. **返回、输出、写文件各有去向**：题目说 returns 就 `return`，由主程序决定输出；说 output 才 `print`。
8. **考场节奏**：每分约 2 分钟；先拿每道大题前几问的声明与简单模块分；写一段运行一次；随时保存（「Save your program as Question1_J25」照做）；截图格要按题目的测试数据跑，输入过程也要截进去。

# P1 打标签指南（T24 用）

> 题型体系：`papers/p1/taxonomy.json` v1.1，9 章 88 个题型。本指南告诉打标签的人（T24，codex）怎样给 `corpus/rows/p1/*.jsonl` 的每一行写 `types`、`tag_confidence`、`tag_note`。设计依据与试标结果见文末。
>
> 引用行一律写纯文本行 id（如 9618_s23_12:4(b)），不加任何括号标记。

## 1. 要写的字段

```json
"types": {"primary": "P1-IR-03", "cross": ["P1-PF-11"]},
"tag_confidence": "high",
"tag_note": "…"
```

- `primary`：**每一行必须有且只有一个**主题型，P1 不允许 null。
- `cross`：副题型，0–2 个，见 §3。没有就写 `[]`。
- `tag_confidence`：`high` 或 `low`，见 §4。
- `tag_note`：`low` 时必写（说明在哪两个题型之间犹豫、为什么）；`high` 时可以不写，遇到本指南里的边界判例可写一句「按指南 §6 第 n 条」。
- 不新建题型码。真的找不到合适的题型 → 选最接近的、标 `low`、`tag_note` 写「无合适题型：…」，由设计工位裁决。

## 2. 定主题型的步骤

1. **先看命令和设问对象**，再看情境。情境（「一家商店的数据库」「一个视频门铃」）只决定题目讲什么故事，不决定题型。例：9618_s23_12:2(c)(i) 在数据库情境里问「怎样校验 RiderLevel 字段」，主题型是 P1-SP-06（数据校验），不是数据库题型。
2. **对照 taxonomy 的 `cues`** 找候选题型，再用该题型的 `not` 排除近邻。
3. **看 MS 得分点**确认：主题型 = 承担得分点最多的那个题型。两个题型分数相同时，取题干命令直接问的那个，另一个写进 `cross`。
4. `has_figure: true` 的行（逻辑电路、E-R 图、汇编表、拓扑图等）**必须看原页**再定：`python skill/cie-9618-cs-tutor/scripts/rows.py render <行 id>`（需要 MS 时加 `--ms`）。
5. 一行只有一个分值但同时问了两件事（「State … and give one example …」）→ 按得分点多数；各占一半时按 §2.3 后半句。

## 3. 副题型（cross）

`cross` 列出**另外承担了至少 1 个得分点**的题型，最多 2 个，同章、跨章都可以（D14）：

- **要加**：某个得分点必须用到另一个题型的知识或套路才能拿到。例：9618_w23_12:8(c)(ii) 问写光盘时地址总线、数据总线和缓冲区的作用——主题型 P1-PF-01（总线），缓冲区那一分属 P1-HW-06，加副题型。
- **要加（同章）**：一张表格把同章两种不同套路混在一起时（如 9618_s24_13:3(b) 的结果表里同时有 LSL 与 XOR/AND：主题型 P1-PF-12，副题型 P1-PF-11）。
- **不加**：只是情境或词汇出现了另一个题型的名字。例：9618_s24_11:2(c)(ii) 固态存储的原理表里要写出 NAND/NOR 两种门，这是固态存储原理本身的内容，不加 P1-LG-01。
- **不加**：主题型的 `summary` 已经覆盖的内容（例如 P1-IR-12 计算时顺带做单位换算，不加 P1-IR-01）。

常见的副题型组合：

| 主题型 | 常见副题型 | 典型行 | 何时加 |
|:--|:--|:--|:--|
| P1-IR-13 / P1-IR-14 压缩 | P1-CM-12 位流 | 9618_s25_11:2(b)(i)、9618_w23_12:6(a) | MS 有「实时观看 / 减少缓冲 / 带宽」类得分点 |
| P1-PF-01 总线 | P1-HW-06 缓冲区 | 9618_w23_12:8(c)(ii) | 同题要说缓冲区作用 |
| P1-PF-06 端口 | P1-SS-01 操作系统 | 9618_w24_11:3(b)(ii) | 得分点含「OS 找到并加载设备驱动」 |
| P1-PF-12 位运算 | P1-PF-11 移位 | 9618_s24_13:3(b) | 同一结果表里既有 AND/OR/XOR 又有 LSL/LSR |
| P1-EO-04 AI 应用 | —（不加 P1-SP-03） | 9618_s24_11:5(c)(ii) | 题干提到生物认证，但 MS 只考人脸识别怎样工作 |
| P1-SP-06 校验 | —（不加 DB 题型） | 9618_s23_12:2(c)(i) | 数据库字段只是情境 |

## 4. 低信心（`tag_confidence: "low"`）

只在下列情况标 `low`，并在 `tag_note` 写清原因：

1. 两个题型各承担约一半得分点，§2 与 §6 都不能裁决。
2. 行带 `ms-misaligned`、`split-uncertain` 或 `ocr-garbled`，看了原页仍无法确定这一格 MS 在考什么。
3. 题目内容在 88 个题型里都找不到合适位置（写「无合适题型」）。
4. 看原页后发现题干与 `stem` 文字明显不符（同时在 `tag_note` 写「行数据疑误」，供总控转修正任务）。

不要因为「题目长」「有图」「是 2021 扩展卷」就标 `low`。目标：低信心 < 10%。

## 5. 特殊行

- **`equivalent_of` 不为空**的行：照抄原行的 `types` 与 `tag_confidence`，不重新判断。
- **2021 扩展卷**（`extension: true`）：同样打标签，规则不变。
- **s26 各卷**：同样打标签（D1 只限制选代表题，不限制打标签）。

## 6. 边界判例（按出现频率排）

1. **数制题组里的移位** → P1-PF-11，不随大题归 IR。例：9618_s23_12:4(d)、9618_s23_11:3(d)(vi)。
2. **字符与码值**：码值已给、只换进制 → P1-IR-02（9618_s25_13:1(c)(ii)、9618_s25_11:3(b)(ii)、9618_s21_12:6(c)(i)）；要利用「码值连续」推出另一字符的码 → P1-IR-06（9618_s21_12:6(c)(ii)：已知 '1' 为 49，求 '5'）。
3. **补码 vs 无符号**：题干出现 two's / one's complement、负数、「smallest … integer」→ P1-IR-03；其余进制转换 → P1-IR-02。补码数做加减 → P1-IR-05。
4. **加减 vs 汇编算术**：裸的二进制加减 → P1-IR-05；在指令表里执行 ADD/SUB/INC → P1-PF-09。
5. **「n 位能表示几个值」**：纯数字 → P1-IR-01（9618_s23_12:4(a)）；问图像颜色数或最少位深 → P1-IR-12（9618_s22_12:1(b)(i)、9618_w24_13:6(b)(i)）。
6. **位图三分**：术语与编码 P1-IR-07，参数改变的影响 P1-IR-08，计算 P1-IR-12。「为什么实际文件比算出来大」→ P1-IR-07（文件头/元数据）。声音同理：P1-IR-10 / P1-IR-11 / P1-IR-12。
7. **压缩三分**：为什么压缩 P1-IR-13；选有损还是无损 P1-IR-14；怎样压缩 P1-IR-15。「降低采样率属于有损还是无损」→ P1-IR-14（9618_w25_12:6(a)）；「描述一种有损压缩声音的方法」→ P1-IR-15。
8. **逻辑六分**：单门 P1-LG-01；表达式→电路 P1-LG-02；电路→表达式 P1-LG-03；表达式或电路→真值表 P1-LG-04；真值表→表达式 P1-LG-05；参数表/文字条件→表达式 P1-LG-06。「找出电路中没有用到的门」→ P1-LG-01。「指出真值表中哪几行错」→ P1-LG-04。
9. **寄存器三分**：单个寄存器作用、通用 vs 专用 → P1-PF-02；放在 F-E 周期顺序里讲、或要写寄存器传送记法 → P1-PF-03（9618_w25_13:6(b) 问 MAR/MDR「在 F-E 周期中」的作用 → PF-03）；CU、时钟、总线 → P1-PF-01。
10. **汇编三分**：独立的几组指令求 ACC/IX → P1-PF-09；有程序流程（跳转、比较、输出、循环）的跟踪表 → P1-PF-10；寻址方式的名称与描述 → P1-PF-08。
11. **位运算三分**：给了指令求结果 → AND/OR/XOR 为 P1-PF-12、移位为 P1-PF-11；给了目标效果要写指令或解释掩码 → P1-PF-13；要写的指令是移位（如 LSL #2）→ P1-PF-11（9618_w25_11:4(a)）。
12. **翻译程序**：描述编译器/解释器怎样工作（含填空）→ P1-SS-04（9618_s25_13:3(a)）；比较优缺点、结合开发阶段选择 → P1-SS-05；两遍汇编器每一遍做什么 → P1-PF-07。
13. **OS 与实用软件**：OS 的管理任务（列名或详述）→ P1-SS-01；具体实用软件（碎片整理、备份、格式化等）→ P1-SS-02。杀毒软件出现在「防范威胁」情境 → P1-SP-03；出现在「OS 自带的实用软件」情境 → P1-SS-02。
14. **安全措施 vs 加密**：看 MS 接受什么。题干点名加密，或问「怎样保护传输中的数据」而 MS 只接受加密 → P1-SP-04（9618_w24_12:4(c)、9618_s25_11:7(a)、9618_s24_12:3(a)(ii)）；问一般措施、MS 接受多种（防火墙、杀毒、密码……）→ P1-SP-03（9618_s24_12:3(a)(i)）；两者各半的表格 → 主题型 P1-SP-03、副题型 P1-SP-04（9618_s25_13:3(b)）。点名数字签名 → P1-SP-05。数据库情境下问 DBMS 怎样保护数据 → P1-DB-08。
15. **校验/验证三分**：校验方法与应用 → P1-SP-06（含「描述校验如何保护完整性」）；验证方法（录入或传输、奇偶、校验和）→ P1-SP-07；两者比较、合用或「通过后仍可能出错」→ P1-SP-08。
16. **完整性的三个去处**：一般的安全/隐私/完整性区分 → P1-SP-01；术语表里给参照完整性下定义 → P1-DB-02（9618_w24_11:2(c)）；解释参照完整性为什么重要、DBMS 怎样保证完整性 → P1-DB-09。
17. **SQL 四分**：建库建表、改表结构、DDL 改错 → P1-DB-10；单表查询 → P1-DB-11；两表查询（含两表查询改错）→ P1-DB-12；INSERT/UPDATE/DELETE → P1-DB-13。「补全 SQL」与「改正 SQL」按语句本身归类。
18. **关系与键**：识别/定义键 → P1-DB-02；描述表间关系、连接表的作用 → P1-DB-03；画 E-R 图 → P1-DB-04；设计新表（含「描述需要增加的表」）→ P1-DB-06。
19. **拓扑**：拓扑特点、比较、选择、画图 → P1-CM-03；数据包在拓扑中怎样走 → P1-CM-04；总线网的冲突 → P1-CM-07；「描述 Ethernet 是什么」→ P1-CM-07。
20. **硬件设备**：路由器、交换机、WNIC 等 → P1-CM-05；调制解调器、PSTN、专线、蜂窝网络 → P1-CM-09。
21. **监测/控制 vs 传感器**：判断系统类型、反馈 → P1-HW-08；选传感器、执行器作用 → P1-HW-09。
22. **AI 两分**：AI 怎样工作 → P1-EO-04；AI 带来的影响 → P1-EO-05。

## 8. 设计说明与试标

- **章节**：按考纲第 1–8 节建章，章码采用任务卡建议；逻辑门（考纲 3.2）每卷必考、套路与硬件描述题不同，按 D15 独立成 LG 章，排在 HW 之后，共 9 章；章内顺序就是学习顺序（先概念后计算、先基础后综合）。
- **粒度**：一个题型 = 识别信号、作答套路、MS 得分句模式都稳定的一种考法。核验语料（2022–26s）中少于 2 次的考法已并入近邻题型：URL/DNS 并入 P1-CM-09，版权并入 P1-EO-03，「为什么需要输入/输出/主存/辅存」并入 P1-HW-01。P1-LG-06（2 次）与 P1-SS-06（3 次）因是考纲独立要求单独保留。
- **试标**：`papers/p1/pilot_tags.csv`（列 `id,primary,cross,confidence,note`，多个副题型用 `;` 分隔），3 份不同考季的卷全部小问（9618_s23_12、9618_w24_11、9618_s25_13，共 88 行，225 分）。每行都找到了主题型；低信心 0 行；带副题型 2 行；用到 53 个题型。13 行碰到边界，都已由 §6 的规则裁决，`note` 列写了依据。
- **试标后回改**：P1-SP-03 / P1-SP-04 的分界从「题干是否点名加密」改为「MS 是否只接受加密」（§6 第 14 条），因为「保护传输中的数据」类题目即使没点名，MS 也只给加密分。
- T24 打完后，若某题型核验语料不足 2 次、或低信心集中在某一对题型，交设计工位复核再定是否合并。

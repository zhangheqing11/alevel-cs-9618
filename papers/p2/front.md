# CIE 9618 Paper 2 · Fundamental Problem-solving and Programming Skills 题型手册

> 2027 年 5–6 月考季用。语料：2022–2026s 全部 variant（核验语料）+ 2021（扩展）。给分依据只认每题自己的 MS；本手册的英文得分句都逐字引自对应 MS，并标出题号。伪代码一律按 2027–29 版剑桥伪代码指南书写（与 `ladder/design.md` §5 速查表、阶梯各级对照卡一致）。

## 使用指南

### 这本手册怎么组织

- **4 章 46 个题型**：AD 算法设计与问题求解 → DT 数据类型与数据结构 → PG 编程 → SD 软件开发。章序按考纲第 9–12 节排；每章内部按“概念 → 读代码 → 写代码”排。
- P2 是**笔答伪代码卷**：分值最大的是 Q6–Q8 的“写一个过程 / 函数”大题（每问 6–8 分）。这些大题按**主要处理的数据结构**归进题型：一维数组、二维数组、记录数组、排序、读文件、写文件、栈 / 队列 / 链表的数组实现都在 DT 章；字符串、日期、数值计算、循环输入在 PG 章。
- 每章开头是**核心思想**和**题型树**（每型的星级、小问数、分值）；章末是**本章易混辨析**。
- 每个题型一张**题型卡**，固定 9 个部分；**写代码类题型**（要写出伪代码、流程图或算法步骤的题型）另加 3 个部分：

| 部分 | 作用 |
|:--|:--|
| 考情 | 构建器按语料自动统计：小问数、分值、出现卷数、设问分布、★ |
| 考法 | 这个题型怎么问、常见几种变化 |
| 识别信号 | 题干里能认出它的英文原词 |
| 解题思路 | 编号步骤，照着做就能写出得分答案 |
| **伪代码模板**（写代码类） | 这类题的标准骨架：模块头、局部声明、初值、主循环、处理、输出 / 返回 |
| 得分表述 | 最常出现、最能拿分的 MS 原句，可直接默写 |
| **得分点地图**（写代码类） | 按该型全部已拆分 MS 得分点统计：哪几分几乎每次都有、对应哪个技能标签 |
| 易错与失分 | 来自 MS 的限定与常见混淆 |
| 代表题精讲 | 一道 2022–25 的典型题：在考什么 → 完整作答（能直接拿满分的伪代码）→ 与 MS 逐点对齐 → 英文作答句 / 规范代码 → 直观 |
| **同题 Python 版要点**（写代码类） | 代表题的 Python 写法与伪代码的不对应之处，以及要先过的阶梯级 |
| 下一道变式 | 同型、换了一个特征的另一题，自己做 |
| 刷题清单 | 构建器自动列出该型全部真题，新卷在前；2021 扩展单列 |

- 另有每章一份**伪代码 ↔ Python 对照与模板**（`P2伪代码与Python对照`）：本章涉及的伪代码结构、对应的 Python 写法、常见失分；术语类（abstraction、decomposition、ADT 等）仍按“英文得分句 / 中文定义 / 直观理解”三层列出。

### 记号

- **题号**写成短格式：`s24/22 Q8(c)` = 2024 年 6 月考季、Paper 2 第 2 套（variant 2）、第 8 题 (c)。季：`s` = 5–6 月，`w` = 10–11 月。
- **“英文句” + 题号**：逐字引自该题 MS 的句子（校验器逐字核对过）。MS 里的伪代码赋值箭头在抽取文本里是私用区字符，本手册一律写成 `←`。
- **MP n**：该题 MS 计分清单的第 n 个得分点（Mark Point）。手册里的“得分点地图”和代表题对齐表都按 MP 编号。
- **技能标签**（如 `loop-to-eof`、`file-close`）：得分点考的那项技能，词表见 `papers/p2/skill_tags.json`。学习记录按标签统计失分，针对性练阶梯。
- **“讲解时请对照原卷 QP p.N”**：这道题要看流程图、表格、代码排版才能讲清，学习时打开原卷第 N 页。
- **★ 星级**由构建器按出现频率与分值算出，★★★ 为几乎每季必考。
- **2026 年 6 月的 12 份卷**（`s26`）留给考前限时整卷模考：专项刷题时跳过；手册的代表题与变式也避开了它们。

### 推荐用法

1. **首学一个题型**：读卡的“考法 → 识别信号 → 解题思路 → 伪代码模板”，再看代表题精讲（直接看讲解，不必先做）。
2. **写代码类题型**：先确认对应阶梯级已过关；然后自己写“下一道变式”的伪代码（手写，计时），按该题 MS 的得分点逐点自批，填得分点表（MP / MS 原文 / 你的写法 / ✓✗ / 技能标签）；再用 Python 写同题，跑测试。
3. **刷题**：从刷题清单里由新到旧取没做过的题；每次批改都对照 MS 原文，把丢分的那个得分点和技能标签记下来。
4. **默写**：“得分表述”、伪代码模板和对照表里的概念句，考前反复默写。
5. 发现卡片里的错误或 MS 引文问题，记到 `handoff/勘误.md`，由总控修正。

## 通用得分规则

以下规则从 MS 的写法归纳而来，适用于全卷。每条都附了一处 MS 原文作例子；具体某题的给分永远以那题自己的 MS 为准。

### 1. 写代码题按得分点给分，范例代码只是一种解法

写模块题的 MS 先给一段 Example solution，再给计分清单（“Mark as follows”“One mark per point”“MP1 … MP8”）。**给分只看清单**：你的算法与范例不同，只要满足得分点描述的意思就给分。清单常常多于分值，用 Max 封顶：「One mark per point (Max 5)」⟦9618_w22_21:3⟧。所以写全每一步，不要赌某一分。

### 2. 有几分必拿：模块头、声明、初值、关闭文件、输出 / 返回

几乎每个写模块题都有这几分，而且与算法难度无关：

- 模块头与结尾：「Function heading, ending and return type」⟦9618_w23_21:4(a)⟧——`FUNCTION … RETURNS …` 与 `ENDFUNCTION` 都要写，参数要带类型。
- 局部变量声明：「Declare Count and Index as integers」⟦9618_w23_21:4(a)⟧。题目写了 All variables used must be declared 时，循环变量也要声明。
- 计数器、累加器赋初值：「Initialise Count」⟦9618_w23_21:4(a)⟧——写在循环**之前**。
- 文件打开要写模式并关闭：「Open both files in correct modes and subsequently close」⟦9618_s24_22:8(c)⟧。
- 最后的输出或返回：「Compare Count with Max and return Boolean in both cases outside the loop」⟦9618_w23_21:4(a)⟧。

### 3. 读懂得分点里的位置限定

| MS 里的写法 | 含义 |
|:--|:--|
| `in a loop` | 这一步必须写在循环体里 |
| `after the loop` / `outside the loop` | 必须写在循环之后（只输出一次） |
| `before the loop` | 初值、打开文件、输入查找值要在循环前 |
| `in both cases` / `in all cases` | 找到和没找到两种情况都要有输出或返回 |
| `following a reasonable attempt` | 前面的主体算法基本写出来了，这一分才给 |
| `(and subsequently close)` | 打开与关闭合成一分，少了关闭这一分整个没有 |
| `Attempt at …` / `Completely correct …` | 同一步拆成两分：写出大意得前一分，完全正确再得后一分 |

例：「Output number of blank lines removed following a reasonable attempt」⟦9618_s24_22:8(c)⟧——只写一句 OUTPUT 而主循环没写，这一分不给。

### 4. 只写伪代码，不混 Python

题目要求 pseudocode 时，混入 Python 语法或插页以外的语言函数（`def`、`print`、`input()`、`len()`、`range()`、切片 `s[1:3]`、`elif`、`==`、`+` 拼接字符串、`for line in file`、靠缩进省掉 `ENDIF`、默认 0 起下标），**该得分点不给**。指南里没有、但也不属于某种语言的写法（`ELSIF`、`ENDFOR`、`INPUT A, B` 一次输入多个）只有该题 MS 显示接受才给，否则按不给处理。本手册与阶梯只教指南写法（决策 D2）。

| 不要写 | 写成 |
|:--|:--|
| `x = x + 1`、`x += 1` | `X ← X + 1` |
| `if a == b:` | `IF A = B THEN … ENDIF` |
| `elif` | `ELSE` 里嵌套 `IF … ENDIF` |
| `for i in range(1, 11):` | `FOR I ← 1 TO 10 … NEXT I` |
| `len(S)`、`S[2:5]`、`str(N)` | `LENGTH(S)`、`MID(S, 3, 3)`、`NUM_TO_STR(N)` |
| `"Total: " + str(T)` | `"Total: " & NUM_TO_STR(T)`，或 `OUTPUT "Total: ", T` |
| `!=` | `<>` |
| `OPEN F FOR READ` | `OPENFILE F FOR READ`（个别 MS 范例写 OPEN，但指南只有 OPENFILE） |

### 5. 不依赖 AND 短路

伪代码不保证 `AND` 短路求值。`WHILE Index <= 500 AND Data[Index] <> 999` 在 Index 到 501 时仍可能去读 `Data[501]`。MS 范例有时这样写并照样给分，但本手册教**标志变量或分层判断**的写法（决策 D25），既拿分又不越界。

### 6. “efficient”= 找到就停、能停就停

题目写 Write efficient pseudocode 时，MS 通常有一分专给“提前结束”：找到目标就退出循环，或利用已排序、未用元素标记（如 999）提前停止：「Efficiency (this scenario): terminate inner loop when ErrCode = 999」⟦9618_w22_22:7(b)⟧。这时用**条件循环**（WHILE / REPEAT）而不是固定次数的 FOR。

### 7. 题目给的名字照抄，指定要用的模块必须调用

数组名、字段名、文件名、模块名一律照题目抄（大小写也照抄）。题目写 Module … must be used in your solution 时，调用它本身就是得分点；函数要在表达式里用、把返回值存起来或直接判断，过程才用 `CALL`。MS 有时宽容 CALL 的误用：「Ignore CALL」⟦9618_w23_23:8(a)⟧——但规范写法仍是函数不用 CALL。

### 8. 输出要带说明文字

“output … with a suitable message”时，输出语句要有说明文字和变量值：「Output an appropriate message in both cases after the loop」⟦9618_w25_21:8(a)⟧。题目给了输出样例时，照样例的文字与顺序写。

### 9. 计算的类型要对

求平均用 `/`（结果是 REAL），不要用 `DIV`：「Reject use of DIV」⟦9618_s24_22:2(a)⟧。要整数结果时用 `INT()` 或题目指定的方法；写进文本文件之前，数值、布尔值要先转成字符串。

### 10. 文字题与 P1 同样的规则

非代码小问（state、explain、describe）与 P1 一样：一个得分点一分，点数要够；有情境就扣情境；题干已给的不再写；选择题分数常在理由上。用文字描述算法时（Do not include pseudocode statements），按 MS 的步骤一句一步写，步骤里要说清循环、条件和位置（in a loop、after the loop），但不能写成伪代码语句。

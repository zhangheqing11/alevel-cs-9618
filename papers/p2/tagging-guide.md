# P2 打标签与得分点拆分指南（T24 用）

> 题型体系：`papers/p2/taxonomy.json` v1.0，4 章 46 个题型；技能标签：`papers/p2/skill_tags.json` v1.0，76 个标签（唯一词表，D8）。本指南告诉打标签的人（T24 的 P2 部分，codex）怎样给 `corpus/rows/p2/*.jsonl` 的每一行写 `types`、`tag_confidence`、`tag_note`，以及怎样给写代码的小问写 `markpoints` 与 `ms_max`。设计依据与试标结果见文末。
>
> 引用行一律写纯文本行 id（如 9618_s24_22:8(c)），不加任何括号标记。

## 1. 要写的字段

```json
"types": {"primary": "P2-DT-07", "cross": ["P2-PG-11"]},
"tag_confidence": "high",
"tag_note": "…",
"markpoints": [
  {"n": 1, "text": "Procedure heading, parameter and ending", "marks": 1, "skills": ["module-header"]}
],
"ms_max": 8
```

- `primary`：**每一行必须有且只有一个**主题型，P2 不允许 null。
- `cross`：副题型，0–2 个，见 §4。没有就写 `[]`。
- `tag_confidence`：`high` 或 `low`，见 §5。`low` 时 `tag_note` 必写；`high` 时可写一句「按指南 §7 第 n 条」。
- `markpoints` / `ms_max`：只给 §8.1 规定要拆的行写；其余行不写这两个字段。
- 不新建题型码，不新建技能标签。找不到合适题型 → 选最接近的、标 `low`、`tag_note` 写「无合适题型：…」；找不到合适技能 → 选最接近的标签，并在 `tag_note` 写「技能词表缺：…」，由设计工位裁决。

## 2. 定主题型的步骤

1. **先看要考生产出什么**，再看情境。P2 的产出只有五类，先据此缩小范围：

   | 考生要产出 | 先看的题型 |
   |:--|:--|
   | 一段伪代码（写模块、补全模块、写算法） | §3 写代码题的归类规则 |
   | 流程图、结构图、状态转换图 | P2-AD-04、P2-SD-03、P2-SD-04 |
   | 用文字描述的算法步骤（Do not include pseudocode） | P2-AD-06 |
   | 表格（数据类型、表达式、追踪表、测试计划、打勾） | P2-DT-01、P2-PG-01、P2-PG-02、P2-PG-03、P2-SD-07、P2-SD-10 等 |
   | 文字解释、说明、列举 | 其余概念题型 |

2. **对照 taxonomy 的 `cues`** 找候选题型，再用 `not` 排除近邻。情境（图书馆、咖啡店、工厂）只决定故事，不决定题型。
3. **看 MS 得分点**确认：主题型 = 承担得分点最多的那个题型；同分时取题干命令直接问的那个。
4. `has_figure: true` 的行（流程图、结构图、状态图、代码清单、追踪表）**必须看原页**：`~/.venvs/alevel-cs/bin/python skill/cie-9618-cs-tutor/scripts/rows.py render <行 id>`（看 MS 加 `--ms`）。rows 的 `ms_text` 丢了 ← 箭头，读代码时注意。
5. **MS 给出两种结构不同的解法时，按题目给定的数据与要求定题型，不按某种解法用到的结构定。** 例：9618_w25_21:6(b) 参数和返回值都是整数，MS 第一种解法先转成字符串再逐位相加，主题型仍是 P2-PG-10，不是 P2-PG-11。

## 3. 写代码题的归类规则

P2 大题（Q6–Q8）的模块往往同时用到文件、数组、字符串。按下面的规则定，不凭整体印象：

1. **数得分点**：MS 中依赖某种结构才能拿到的得分点算这个结构的分。模块头、声明、通用输出这类点不算任何结构。
2. **≥ 2 个得分点的结构算「在场」**。在场的结构按下表优先级取第一个作主题型：

   | 优先级 | 结构（判断信号） | 题型 |
   |:--|:--|:--|
   | 1 | 用数组 + 指针实现栈、队列、链表 | P2-DT-16 |
   | 2 | 排序（冒泡） | P2-DT-08 |
   | 3 | 写文件（WRITE / APPEND、复制、过滤） | P2-DT-10 |
   | 4 | 只读文件（READ、EOF 循环） | P2-DT-09 |
   | 5 | 记录数组（`数组[i].字段`） | P2-DT-07 |
   | 6 | 二维数组 | P2-DT-06 |
   | 7 | 一维数组（含并行数组） | P2-DT-05 |
   | 8 | 日期函数 | P2-PG-12 |
   | 9 | 字符串处理（逐字符、子串、拆字段、拼接） | P2-PG-11 |
   | 10 | 对参数或少数输入值做计算判断 | P2-PG-10 |
   | 11 | 循环读入一串键盘输入并统计 | P2-PG-09 |

3. **第二个在场的结构**写进 `cross`（最多再加一个，见 §4）。
4. 只有「写一条语句/表达式」的小问不走本规则：按 P2-PG-03、P2-DT-02、P2-DT-03、P2-PG-07、P2-PG-12 的 cues 定。
5. 「补全伪代码」（Complete the pseudocode for …）与「写伪代码」同样处理。
6. 题目要求「用文字描述算法、不写伪代码」→ 主题型一律 P2-AD-06，本节规则只用来定 `cross`。流程图（P2-AD-04）同理。

例：9618_s24_22:8(c) 读一个文件、处理后追加到另一个文件，字符串处理由已写好的模块完成 → 写文件在场，主题型 P2-DT-10，不加 P2-PG-11。9618_w25_21:4(a) 输入一串数存进数组：一维数组 3 分、循环输入 2 分 → 主题型 P2-DT-05，副题型 P2-PG-09。

## 4. 副题型（cross）

`cross` 列出**另外承担得分点**的题型，最多 2 个，同章、跨章都可以（D14）：

- **写代码、流程图、算法描述类**（§3 适用的行）：另一个结构在场（≥ 2 个得分点）才加。只有 1 个得分点的输入、输出、调用不加，否则几乎每个模块都要加 P2-PG-09。
- **其他行**：另一个题型承担了至少 1 个得分点就加。例：9618_w22_23:5(b)(ii) 过程改函数（P2-PG-06），其中一分是「返回 StockItem 记录」→ 加 P2-DT-02；9618_w25_21:1(a) 补全表达式（P2-PG-03），一行要用日期函数 → 加 P2-PG-12。
- **不加**：只是情境里出现了另一个题型的词。例：9618_w22_23:5(a)(i) 的 BYREF 是模块头的一部分，不加 P2-PG-07；追踪表里的代码有文件或字符串，不加对应写代码题型。

常见组合：

| 主题型 | 常见副题型 | 典型行 | 何时加 |
|:--|:--|:--|:--|
| P2-AD-06 文字描述算法 | P2-PG-09、P2-DT-05、P2-DT-09 | 9618_w22_23:3、9618_w22_23:7(b)(ii) | 描述的算法里该结构在场 |
| P2-AD-04 流程图 | P2-DT-05、P2-PG-10 | 9618_w25_21:2、9618_s24_22:2(a) | 同上 |
| P2-DT-05 一维数组 | P2-PG-09 | 9618_w25_21:4(a) | 循环输入 ≥ 2 分 |
| P2-DT-09 / P2-DT-10 文件 | P2-PG-11、P2-DT-07 | — | 逐行拆字段或写记录数组 ≥ 2 分 |
| P2-SD-12 修改程序 | P2-DT-02 | 9618_w25_21:8(c) | 有得分点要改记录结构 |
| P2-PG-06 模块概念 | P2-DT-02 | 9618_w22_23:5(b)(ii) | 有得分点涉及记录类型 |

## 5. 低信心（`tag_confidence: "low"`）

只在下列情况标 `low`，并在 `tag_note` 写清原因：

1. 两个题型各承担约一半得分点，§2–§4 与 §7 都不能裁决。
2. 行带 `needs-review` 或 `split-uncertain` 等标记，看了原页仍无法确定这一格 MS 在考什么。
3. 46 个题型里都找不到合适位置（写「无合适题型」）。
4. 看原页后发现题干与 `stem` 明显不符（`tag_note` 写「行数据疑误」，供总控转修正任务）。

不要因为「题目长」「有图」「是 2021 扩展卷」就标 `low`。目标：低信心 < 10%。

## 7. 边界判例（按出现频率排）

1. **写模块 vs 写一条语句**：要写 PROCEDURE/FUNCTION 或多行算法 → §3；只写一条语句或表达式 → P2-PG-03（日期为主 → P2-PG-12，记录字段 → P2-DT-02，数组声明 → P2-DT-03，模块头 → P2-PG-07）。
2. **分解 vs 模块概念**：把问题拆成模块、写模块名与用途、说明程序分阶段的理由 → P2-AD-02（9618_s24_22:8(a)）；为什么用子程序或库程序、过程与函数的区别、参数术语、局部与全局 → P2-PG-06。
3. **抽象 vs 分解**：挑选需要/不需要的数据项、列出对数据的操作 → P2-AD-01；要写模块 → P2-AD-02。
4. **数据类型 vs 标识符表**：表格只填类型 → P2-DT-01；要填变量名、说明、示例值，或问怎样记录变量 → P2-AD-03（9618_s24_22:1(c)）。
5. **输入算法 vs 计算函数**：反复输入（定次数、到哨兵值、到合法为止）→ P2-PG-09；对参数或一次输入的几个值做计算判断 → P2-PG-10（9618_s24_22:4 只输入三条边一次 → P2-PG-10）。
6. **字符串 vs 数值**：参数是字符串、MS 主要考子串与逐字符 → P2-PG-11；本质是算术（逐位求和、校验位）→ P2-PG-10（§2 第 5 条）。
7. **ADT 四分**：特征、选择、识别 → P2-DT-12；在图上做栈操作 → P2-DT-13，队列 → P2-DT-14，链表 → P2-DT-15；怎样用数组和变量实现（含描述声明与初始化、写 Push/AddTo 代码、补全初始化流程图）→ P2-DT-16。「描述入队、出队操作及要做的满/空检查」→ P2-DT-14（9618_w22_23:4(b)(i)）；「描述实现队列要声明与初始化什么」→ P2-DT-16（9618_w22_23:4(b)(ii)）。
8. **文件三分**：只读 → P2-DT-09；有写 → P2-DT-10；不写代码、只问用途/模式/格式/文件名/写前要转换 → P2-DT-11（9618_w25_21:4(b)(ii)、9618_s24_22:6(b)(i)）。
9. **数据结构的选择**：内存中的结构（变量、数组、记录、记录数组）→ P2-DT-04；ADT → P2-DT-12；文件或文件内格式 → P2-DT-11。
10. **读代码四分**：逐行记录变量 → P2-SD-07；指出错并改正 → P2-SD-06；代码没错、问作用、初值、某分支为何执行不到、多余语句、在什么条件下结果才对 → P2-SD-08（9618_w25_21:5(a)(i)）；问循环是否合适 → P2-PG-05（9618_w25_21:5(b)(i)）；问为何低效、怎样更高效 → P2-PG-08。
11. **错误三分**：错误类型的概念、为什么编译器发现不了、IDE 怎样定位 → P2-SD-05；在给定代码里找具体错误 → P2-SD-06；问运行时程序停止响应属于哪类错 → P2-SD-05（9618_s24_22:5(b)）。
12. **测试两分**：测试方法的名称、含义、适用阶段 → P2-SD-09；具体测试数据、补测试计划、给能暴露问题的输入、对参数应做哪些检查 → P2-SD-10（9618_w25_21:6(a) 构造能通过校验位的错误输入 → P2-SD-10）。
13. **改程序**：原代码有错 → P2-SD-06；需求变了要怎样改（写改动行、移动行、描述改动、概述新设计）→ P2-SD-12；只问是哪种维护 → P2-SD-11。
14. **选择结构改写 vs 不可达分支**：要写出改写后的 IF/CASE → P2-PG-04；问哪个分支永远不执行、为什么 → P2-SD-08。
15. **结构图两分**：画、补全、解释符号与关系 → P2-SD-03；由结构图写模块头 → P2-PG-07。
16. **生命周期两分**：阶段、活动、文档、生命周期本身的作用 → P2-SD-01（9618_w22_23:1(b)(i)）；瀑布/迭代/RAD → P2-SD-02。
17. **流程图三分**：画或补全 → P2-AD-04（按标号补全流程图框内文字也在这里）；流程图 → 伪代码 → P2-AD-05；给流程图填追踪表 → P2-SD-07。
18. **良好实践**：常量、注释、缩进、有意义的名称为何好 → P2-PG-08；但只问变量名为何不好或怎样记录变量 → P2-AD-03。

## 8. 得分点拆分规则

### 8.1 哪些行要拆

同时满足下面三条的行写 `markpoints`：

1. `component = 2`；
2. `marks >= 4`；
3. 考生产出的是**伪代码、流程图或文字算法步骤**：主题型属于下表「总是拆」，或属于「作答是代码时拆」且该行的作答确实是伪代码或流程图。

| 类别 | 题型 |
|:--|:--|
| 总是拆 | P2-AD-04、P2-AD-05、P2-AD-06、P2-DT-05、P2-DT-06、P2-DT-07、P2-DT-09、P2-DT-10、P2-PG-09、P2-PG-10、P2-PG-11、P2-PG-12 |
| 作答是代码时拆 | P2-DT-02（写 TYPE）、P2-DT-08（写排序）、P2-DT-16（写 Push 等代码或补全流程图）、P2-PG-04、P2-PG-07、P2-SD-12（写出修改后的代码） |
| 不拆 | 其余题型；以及上面题型里作答是文字解释或单行表格的行（如 9618_w22_23:4(b)(ii) 文字描述队列的声明与初始化） |

表格题（P2-DT-01、P2-PG-02、P2-PG-03、P2-SD-07、P2-SD-10…）即使 ≥ 4 分也不拆：每行一分，没有可复用的技能分解。

### 8.2 怎样切

1. **找到 MS 的计分清单**（「Mark as follows」「One mark per point」「MP1 … MP9」「1 … 2 …」）。范例代码（Example solution）**不拆**，只用来理解得分点。
2. **一个编号 = 一条 markpoint**。`n` 从 1 连续编号，是我们自己的顺序号；MS 编号跳号或错号时以我们的顺序为准。
3. **`text` = MS 原文**：去掉行首的编号（`1`、`MP1`、`1.`、`MP 1`）；跨行的原文用一个空格接起来；其余逐字照抄，包括 `…`、`...`、`//`、`in a loop`、`following a reasonable attempt at MP3`、错别字。校验方法：把 `text` 与该行 `ms_text` 都压缩连续空白后，`text` 必须是子串。
4. **`marks`** 一般为 1。MS 明写一个点值 2 分时照写。
5. **一个编号下有两行各自可得分的子行**（以 `...` / `…` 开头的续行），而编号点的总数少于该行分值时，把子行拆成两条 markpoint。例：9618_w25_21:8(a) 共 7 分，MS 只编到 6，第 5 点含「... and that OnLoan = TRUE in a loop」「... if so, then increment Count in a loop」两行 → 拆成 n=5、n=6，原第 6 点成为 n=7。编号点数已等于分值时，子行不拆，整段作一条（用空格接起来）。
6. **MS 有 `Max n` 或得分点总分大于小问分值** → 写 `ms_max`（取 Max 后的数；没写 Max 时取小问分值）。得分点总分等于分值时不写 `ms_max`。例：9618_s24_22:6(a) 列 8 点、Max 7 → `ms_max: 7`；9618_w22_23:7(a) 列 9 点、Max 8 → `ms_max: 8`。
7. **MS 给了两套各自独立的计分清单**（如「Example solution – conditional」与「Alternative FOR loop example solution」各有 Mark as follows）→ **只拆第一套**，`tag_note` 写「MS 另有替代计分清单：…（一句话说明差别）」。例：9618_w25_21:4(a)（条件循环 / FOR + BREAK）、9618_w25_21:6(b)（转字符串 / MOD 与 DIV）。只有替代范例代码、没有第二套清单的（9618_w25_21:8(b)），按唯一一套清单拆。
8. **同一得分点内的 `//` 或 `/` 并列写法**属于同一条，不拆开。
9. **「One mark per underlined phrase / part」「One mark per row」** 这类没有逐点文字的 MS（常见于 TYPE、数组声明、模块头，如 9618_w25_22:7(b)）：不写 `markpoints`，`tag_note` 写「MS 按下划线/按行给分，未拆」；这不算低信心，`tag_confidence` 照常判断。

### 8.3 怎样打技能标签

每条 markpoint 打 **1–3 个**标签，取「拿不到这一分最可能是因为不会哪项技能」。只用 `skill_tags.json` 里的标签。

| MS 常见写法 | 标签 |
|:--|:--|
| Procedure / Function heading (and ending) including parameters (and return type) | `module-header` |
| … and use of BYREF … | `byval-byref` |
| Declare (local) variables … / Declaration of … | `declare-variables`；写明了类型要求（as REAL、Integers）再加 `data-types` |
| Initialise … / Declaration and initialisation of … | `initialise-variables`（含声明时加 `declare-variables`） |
| (Appropriate) prompt and input … | `input-prompt` |
| Output … (with a suitable message) (after the loop / in both cases) | `output-format` |
| Return … (after loop / in all cases) | `return-value`；返回 TRUE/FALSE 用 `boolean-return` |
| Loop for n iterations / through all elements / to length of string | `loop-bounds`（再按循环种类加 `count-loop` / `char-loop`） |
| Conditional loop … until found OR end of array / file | `pre-condition-loop` 或 `post-condition-loop`；「找到就停」加 `linear-search`；两个条件加 `logic-ops` |
| Loop until EOF(…) | `loop-to-eof` |
| Open … in READ mode / Read a line … in a loop | `file-open-read` |
| Open both files in correct modes and subsequently close | 按模式取 `file-open-read`、`file-write` / `file-append`，再加 `file-close` |
| Write … to the file / WRITEFILE | `file-write`（写前拼行用 `string-concat`、转字符串用 `type-conversion`） |
| Extract a character (in a loop) / Use of MID() | `string-functions`，逐字符时加 `char-loop` |
| Extract field … / test for separator (comma) | `field-extract` |
| Concatenate … / build string | `string-concat` |
| Test if char is alphabetic / non-space / same case | `char-compare` |
| Convert … to string / integer | `type-conversion` |
| Increment count / add to total in a loop | `accumulator` |
| … largest / smallest | `max-min` |
| Set flag … / terminate loop if found | `flag-variable`（找到就停再加 `linear-search`） |
| Reference … with correct .dot notation / test … field | `array-of-records` |
| Array[i, j] / column 1 | `array-2d` |
| Use / call of Module() / assign return value from … | `procedure-call` |
| Use RAND() … | `random-numbers` |
| Use of MOD / DIV / INT | `div-mod` |
| Average / calculation (Reject use of DIV) | `operator-precedence` |

## 10. 设计说明与试标

- **章节**：按考纲第 9–12 节建 4 章，章码采用任务卡建议；章内顺序就是学习顺序（概念 → 读代码 → 写代码）。写代码的大题按 §3「在场结构 + 优先级」归章：ADT 实现、排序、文件、各类数组归 DT；日期、字符串、数值、输入算法归 PG。优先级把「更难、更少见、MS 得分点更依赖的结构」排在前面，保证同一道 Q8 不会因打标签人不同而落到不同题型。
- **粒度**：一个题型 = 识别信号、作答套路、MS 得分点模式都稳定的一种考法。写代码题按「主要处理的数据结构」而不是按情境或模块名分；P2-DT-08（核验语料 3 次，含 s26）因考纲 10.2 点名要求单独保留。
- **技能词表**：`ladder/design.md` §7.8 的 68 个标签全部保留、不改名（阶梯练习 `meta.skills` 不受影响）。任务卡建议的 `procedure-header`、`declare-locals`、`mid-substring`、`concatenate`、`byref-param` 是种子标签的同义词，已分别并入 `module-header`、`declare-variables`、`string-functions`、`string-concat`、`byval-byref`，不另立。新增 8 个 P2 得分点常见技能：`data-types`、`initialise-variables`、`flag-variable`、`max-min`、`random-numbers`、`field-extract`、`declare-array`、`flowchart-draw`。分 15 组：design、data、io、control、structure、algorithm、string、date、array、record、file、adt、oop、exception、p4。
- **试标**：`papers/p2/pilot_tags.csv`（列 `id,primary,cross,confidence,note`，多个副题型用 `;` 分隔），3 份不同考季的卷全部小问（9618_w22_23、9618_s24_22、9618_w25_21，共 66 行，225 分）。每行都找到了主题型；低信心 0 行；带副题型 8 行；用到 33 个题型。`papers/p2/pilot_markpoints.jsonl`（每行 `{"id", "ms_max", "markpoints"}`，`ms_max` 为 null 表示不写该字段）：18 行需拆分的小问拆出 110 条得分点，用到 42 个技能标签；每条 `text` 已核对为 MS 原文子串（压缩空白后），每个技能都在词表里，每行得分点总分等于分值或带 `ms_max`。
- **试标中补充的规则**：① 9618_s24_22:8(c)（文件 + 字符串）、9618_w25_21:4(a)（数组 + 循环输入）按整体印象两种归法都说得通，由此把 §3 定成「≥ 2 分在场 + 优先级」并把副题型门槛定为 ≥ 2 分；② 9618_w25_21:6(b) 暴露「按 MS 解法定结构」会把数值题判成字符串题，加 §2 第 5 条；③ 9618_w25_21:8(a) 暴露 MS 编号少于分值，加 §8.2 第 5 条。

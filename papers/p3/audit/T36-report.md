## warn 逐条说明（本次无 error）

### F10 · CT-02 代表题照抄的官方二分查找会读 Names[0]

- 位置：`papers/p3/cards/CT.md:224`（代表题“完整作答”）；P3-CT-02；`algorithm-trace`。
- 原件与判断：9618_s24_31:10(b)。QP p.10 给出框架（含 `IF TopOfList >= EndOfList THEN` 与 `EndOfList ← CurrentItem – 1`），MS p.12 填空为 “Found ← FALSE”“WHILE Found = FALSE AND NotInList = FALSE”“TopOfList ← CurrentItem + 1” 等。按原页逐行翻译成程序运行（`recompute.py`）：目标比 Names[1] 还小时，范围收到 TopOfList = 1、EndOfList = 2，CurrentItem = 1，判断 `1 >= 2` 为假，走 `EndOfList ← 0`；下一轮 `CurrentItem ← (1 + 0) DIV 2 = 0`，读 Names[0]，越出 `ARRAY[1:100000]`。其余输入（在表中、比 Names[100000] 大、落在两项之间）都正常。卡在 CT.md:195 对 w22_31:12(a) 的同类问题写了“填空照 MS 填；自己写时用模板”，对本题却把整段称为完整作答，没有提示。填空按 MS 给分不受影响，但学生会把这段当作可照抄的二分查找。
- 建议：代表题后加一句：题给框架在目标小于 Names[1] 时会读 Names[0]，填空照 MS 填，自己写用卡里 `WHILE Low <= High` 的模板（模板已用程序验证正确）。

### F11 · CT-06 把“空栈时 Top = Base − 1”说成本型语料的通例

- 位置：`papers/p3/cards/CT.md:524`；同一说法在 `papers/p3/core/CT.md:40`；P3-CT-06；`concept`。
- 原件与判断：卡称“本型语料里的题（w23、w25 两季，以及 2021 扩展卷）Top 都指向栈顶那个值……空栈时 Top = Base − 1”。9618_w25_33:10(b) 的 MS p.13 原文 “MP2 Base pointer with appropriate value (0 or 1)”“MP3 Top pointer with appropriate value (–1, 0, 1)”，范例 `Base ← 0`、`Top ← 0`；9618_w25_31:9(a)(i) 的 MS 判空同时接受 “Top > –1 // Top >= Base”。“都”不成立。学生在初始化题里照卡写不会丢分（MS 接受多种），但会以为只有一种约定，读到 w25_33 的范例时困惑。
- 建议：改为“本型多数题……；w25_33:10(b) 的 MS 对初值接受 –1、0、1，范例 Base = 0、Top = 0——先看题目约定，自己设计时选一种并在 Push / Pop 里保持一致”，core/CT.md:40 同步。

### F08 · SC-01 解释“MS 为什么把私钥写成用来解密”的理由与题干背景相反

- 位置：`papers/p3/cards/SC.md:66`；P3-SC-01；`concept`。
- 原件与判断：卡说 9618_w22_31:6(a) 的 MS 把私钥写成 “used to decrypt data that was encrypted with its matching public key”，“是因为该题背景是私密消息”。QP p.6 题干背景原文：“A message is encrypted using a private key and sent to an individual using asymmetric encryption.”——用私钥加密，正是已验证消息的场景，同一手册 SC.md:351 也照抄了这句。所以 MS 的定义与题干背景并不一致，卡给的理由是错的。章首的密钥用法表、SC-02、SC-06 的结论本身都对（条件性规则写得清楚），错的只是这一句解释。
- 建议：改为“该题 MS 按私钥的常见定义（解密用配对公钥加密的数据）给分，虽然题干背景是用私钥加密；定义题照 MS 写，过程题按场合选钥匙（SC-02、SC-06）”。

### F05 · BL-07 关于 w24_31:7(d)(ii) 的说明停在 D41 裁决之前

- 位置：`papers/p3/cards/BL.md:407`；P3-BL-07；`other`。
- 原件与判断：MS p.10 原页渲染核对，印 “(T =) D.(A.B̅)”。按 QP p.6 真值表（T = 1 的行为 0001、0011、1001、1011、1101、1111）验算：(d)(i) 的 A.D + B̅.D 与 D.(A + B̅) 都与真值表一致，D.(A.B̅) 不一致（`truth_tables.py`）。卡的教学结论（按 D.(A + B̅) 学）正确，但写的是“这处 MS 印刷疑误已报总控裁决”；D41 ② 已裁定为官方笔误，并规定“给分仍按 MS（该点给‘最简形式’）”。卡没有写给分口径，措辞也过时。
- 建议：按 D41 ② 改写：官方笔误、正确式 D.(A + B̅)、批改时该点按“最简形式”给分。

3. **选题规则**：155 个入口（79 道代表题 + 76 道变式；HV-04、BL-02、BL-03 按 D41 写明无第二道）用脚本检查年份、主题型、不同卷、非 s26、非 `equivalent_of`，D41 ① 的例外按清单放行。唯一不符脚本规则的是 AI-07 的变式（主题型 AI-06），D41 ① 已接受，列入“需要总控决定”。

## 脚本用法

全部在仓库根目录用共享环境运行，只读源文件，不改手册：

```
~/.venvs/alevel-cs/bin/python papers/p3/audit/check_handbook.py              # 选题、页码、伪代码 lint、Python 片段（JSON）
~/.venvs/alevel-cs/bin/python papers/p3/audit/check_handbook.py --stats      # 章分量
~/.venvs/alevel-cs/bin/python papers/p3/audit/check_handbook.py --map P3-CT-02    # 重算得分点地图
~/.venvs/alevel-cs/bin/python papers/p3/audit/check_handbook.py --rows <行 id> …  # 题干 / MS / ER
~/.venvs/alevel-cs/bin/python papers/p3/audit/check_handbook.py --render <行 id> [--ms]   # 渲染原页（$T36_RENDER）
~/.venvs/alevel-cs/bin/python papers/p3/audit/check_handbook.py --packet BL  # 一章的卡 + 代表题原页文字
~/.venvs/alevel-cs/bin/python papers/p3/audit/check_handbook.py --verify-pages    # 语料文字 ↔ PDF 原页
~/.venvs/alevel-cs/bin/python papers/p3/audit/check_handbook.py --cross-quotes    # 挂在别章题型行上的引文
~/.venvs/alevel-cs/bin/python papers/p3/audit/check_handbook.py --validate   # findings 与 coverage 格式、输入哈希
~/.venvs/alevel-cs/bin/python papers/p3/audit/truth_tables.py                # BL 章 32 项真值表验算
~/.venvs/alevel-cs/bin/python papers/p3/audit/recompute.py                   # 浮点、RPN、Dijkstra、A*、查找、排序、追踪
~/.venvs/alevel-cs/bin/python papers/p3/audit/check_front_back.py            # back.md 例题题型与卷面顺序统计
~/.venvs/alevel-cs/bin/python papers/p3/audit/make_coverage.py               # 重新生成 T36-coverage.json
~/.venvs/alevel-cs/bin/python papers/p3/audit/add_findings.py <file.json>    # 追加人工写的 findings（先校验字段）
```

`--validate` 会比对 `T36-coverage.json` 里 20 个输入文件的 SHA-256：手册在审计后被改动，校验就失败，避免把未审的新内容当作已审。

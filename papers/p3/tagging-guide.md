# P3 打标签与得分点拆分指南（T31 用）

> 题型体系：`papers/p3/taxonomy.json` v1.0，9 章 79 个题型；技能标签：`papers/p2/skill_tags.json`（唯一词表，D8）+ 本指南 §8.4 的 2 个提议标签（待总控批准）。本指南告诉打标签的人（T31）怎样给 `corpus/rows/p3/*.jsonl` 的每一行写 `types`、`tag_confidence`、`tag_note`，以及怎样给写代码的小问写 `markpoints` 与 `ms_max`。设计依据、试标结果与考纲核对见文末 §10–§11。
>
> 引用行一律写纯文本行 id（如 9618_s24_31:10(b)），不加任何括号标记。

## 1. 要写的字段

```json
"types": {"primary": "P3-CT-02", "cross": []},
"tag_confidence": "high",
"tag_note": "…",
"markpoints": [
  {"n": 1, "text": "Found ← FALSE", "marks": 1, "skills": ["initialise-variables", "flag-variable"]}
],
"ms_max": 4
```

- `primary`：**每一行必须有且只有一个**主题型，P3 不允许 null。
- `cross`：副题型，0–2 个，见 §4。没有就写 `[]`。
- `tag_confidence`：`high` 或 `low`，见 §5。`low` 时 `tag_note` 必写；`high` 时可写一句「按指南 §7 第 n 条」。
- `markpoints` / `ms_max`：只给 §8.1 规定要拆的行写；其余行不写这两个字段。
- 不新建题型码，不新建技能标签。找不到合适题型 → 选最接近的、标 `low`、`tag_note` 写「无合适题型：…」；找不到合适技能 → 选最接近的标签，`tag_note` 写「技能词表缺：…」，由设计工位裁决。

## 2. 定主题型的步骤

1. **先看要考生产出什么**，再看情境。P3 的产出分六类，先据此缩小范围：

   | 考生要产出 | 先看的章节与题型 |
   |:--|:--|
   | 伪代码（TYPE、CLASS、补全算法、文件处理） | DR-02 ～ DR-05、CT-02、CT-03、CT-06 ～ CT-09、FP-06、FP-10 |
   | 其他「代码」：汇编、Prolog 子句、BNF | FP-03、FP-07 ～ FP-09、SY-08 |
   | 计算或按步骤填表（浮点、RPN、真值表、卡诺图、Dijkstra、A*、追踪表） | DR-09 ～ DR-11、SY-11、SY-12、BL-01、BL-04 ～ BL-07、AI-03、AI-04、CT-12 |
   | 图（语法图、逻辑电路、类图、二叉树结点图、协议栈图） | SY-09、BL-03、FP-05、CT-09、CI-02 |
   | 连线、填表、选词填空 | 按表中内容属于哪个知识点定（见 §7 第 18 条） |
   | 文字描述、解释、比较 | 其余概念题型 |

2. **对照 taxonomy 的 `cues`** 找候选题型，再用 `not` 排除近邻。情境（诊所、出租车公司、图书馆）只决定故事，不决定题型。
3. **看 MS 得分点**确认：主题型 = 承担得分点最多的那个题型；同分时取题干命令直接问的那个，另一个写进 `cross`。
4. `has_figure: true` 的行**必须看原页**：`~/.venvs/alevel-cs/bin/python skill/cie-9618-cs-tutor/scripts/rows.py render <行 id>`（看 MS 加 `--ms`）。特别注意：
   - 布尔表达式的上划线（取反）在 `stem` 与 `ms_text` 里全部丢失（`A.B.C` 可能是 `Ā.B.C̄`），逻辑与卡诺图题只能看原页判断；
   - 补全伪代码题要在 QP 原页数留空的行（§8.2 B）；
   - `ms_text` 的 ← 箭头在少数行丢失（`MaxSize     1000`），读代码时注意；`⇨`、`∞` 已按 D29 归一。
5. 同一题组的各小问**各自**定题型，不随大题。例：9618_s24_31:6(a) 真值表 BL-01、9618_s24_31:6(b) 积之和 BL-04、9618_s24_31:6(c)(i) 填卡诺图 BL-05、9618_s24_31:6(c)(ii) 与 9618_s24_31:6(c)(iii) 圈组与化简 BL-06。

## 3. P3 的写代码小问怎样归类

P3 的写代码小问几乎都是「一个结构、一个题型」，不需要 P2 §3 那样的优先级表。按**数据存在哪里、怎样走**定：

| 代码处理的对象 | 题型 |
|:--|:--|
| 一维数组上的线性查找或二分查找（含函数形式、变量说明表） | P3-CT-02 |
| 数组排序（插入、冒泡，含并行数组同步交换） | P3-CT-03 |
| 数组 + 顶指针实现的栈（声明、初始化、Push、Pop、调用） | P3-CT-06 |
| 数组 + 首尾指针实现的队列 | P3-CT-07 |
| 数据数组 + 指针数组的单链表（沿 NextPointer 走） | P3-CT-08 |
| 左右指针的二叉树（沿 LeftPtr / RightPtr 走，含记录数组表示） | P3-CT-09 |
| 文件（随机文件 SEEK/GETRECORD/PUTRECORD，或文本文件读写） | P3-FP-10 |
| TYPE … ENDTYPE / 枚举 / 指针 / 集合 | P3-DR-03 / P3-DR-02 / P3-DR-05 |
| CLASS … ENDCLASS | P3-FP-06 |

- 「在 X 里查找」按 X 定，不归 CT-02：沿链表查找 → CT-08（9618_w22_32:11(b)）；在二叉树里查找 → CT-09（9618_w24_31:11(c)）；在随机文件里逐个位置找空位或找记录 → FP-10（9618_s25_33:11、9618_w23_32:12(b)）。
- 写代码小问的副题型门槛同 P2：另一个结构承担 ≥ 2 个得分点才加。只有 1 分的输入、输出、标志变量不加。
- 「补全伪代码」（Complete the pseudocode …）与「写伪代码」同样处理。

## 4. 副题型（cross）

`cross` 列出**另外承担得分点**的题型，最多 2 个，同章、跨章都可以（D14）：

- **写代码行**：见 §3 末，≥ 2 个得分点才加。
- **其他行**：另一个题型承担了至少 1 个得分点就加。例：9618_s24_31:4(b) 问顺序存取怎样用于串行文件与顺序文件，MP1、MP3 讲记录怎样排列（组织方式）→ 主题型 DR-07，副题型 DR-06；9618_w22_31:7(c) 2 分写化简积之和、1 分用布尔代数写最简形式 → 主题型 BL-06，副题型 BL-07。
- **不加**：主题型的 `summary` 已经覆盖的内容。例：9618_s25_33:7 SSL/TLS 握手里请求并验证证书是 SC-04 的一部分，不加 SC-05；9618_w22_32:4(b) 记录字段用了 4(a) 的枚举类型，只占一分且属记录声明本身，不加 DR-02；9618_w25_31:7(b) 描述深度学习时一分提到反向传播，不加 AI-07。
- **不加**：只是情境里出现了另一个题型的词。例：9618_s25_31:4(c)「二叉树可用递归实现」，问的是还有哪种 ADT 可递归实现 → CT-10，不加 CT-09。

常见组合：

| 主题型 | 常见副题型 | 典型行 | 何时加 |
|:--|:--|:--|:--|
| P3-DR-07 文件存取 | P3-DR-06 组织方式 | 9618_s24_31:4(b) | 有得分点讲记录怎样排列 |
| P3-DR-07 文件存取 | P3-DR-08 散列 | 9618_s24_32:7(b)(ii) | 有得分点讲冲突处理（线性探测、溢出区） |
| P3-BL-06 卡诺图化简 | P3-BL-07 布尔代数 | 9618_w22_31:7(c) | 同一小问另有「simplest form」得分点 |
| P3-CT-01 查找方法 | P3-CT-04 大 O | 9618_s24_32:8(b) | MS 另有一组大 O 得分点 |
| P3-CI-07 交换比较 | — | 9618_s22_31:3 | 两种交换都问时主题型已覆盖，不加 CI-05/CI-06 |

## 5. 低信心（`tag_confidence: "low"`）

只在下列情况标 `low`，并在 `tag_note` 写清原因：

1. 两个题型各承担约一半得分点，§2–§4 与 §7 都不能裁决。
2. 看了原页仍无法确定这一格 MS 在考什么（例如抽取把相邻小问的 MS 混在一起）。
3. 79 个题型里都找不到合适位置（写「无合适题型」）。
4. 看原页后发现题干与 `stem` 明显不符（`tag_note` 写「行数据疑误」，供总控转修正任务）。

不要因为「题目长」「有图」「是 2021 扩展卷」就标 `low`。目标：低信心 < 10%。

## 6. 特殊行

- **`equivalent_of` 不为空**的行：照抄原行的 `types`、`tag_confidence`、`markpoints`、`ms_max`。
- **逐字相同但没标 `equivalent_of` 的行（共 119 行）**：`stem` 与 `ms_text` 压缩连续空白后与同季另一 variant 的同题号行完全相同。分布：9618_s22_33 / 9618_s23_33 / 9618_s24_33 / 9618_w22_33 / 9618_w23_33 / 9618_w24_33 与同季 _31（共 76 行，核验语料），9618_s21_32 / 9618_s21_33 / 9618_w21_32 与同季 _31（共 43 行，2021 扩展）。它们多是带图的行，抽取时没被识别为重复。总控补 `equivalent_of` 之前：打标签时先比对（压缩空白后 `stem` 与 `ms_text` 都相同），相同就照抄 _31 卷同题号行的全部字段。
- **2021 扩展卷**（`extension: true`）与 **s26 各卷**：同样打标签、同样拆得分点（D1 只限制选代表题）。
- **看图行**：见 §2 第 4 条。逻辑题、卡诺图题若需要判断表达式内容（例如 BL-06 与 BL-07 的分界），必须看 MS 原页的上划线。

## 7. 边界判例（按出现频率排）

1. **浮点四分**：给的是十进制数、要写出浮点表示 → DR-10；给的是浮点位串、要求十进制值 → DR-09；给的是二进制数或未规格化的位串要规格化、问为何不是规格化、问规格化的理由、求最大正数或最小数 → DR-11（9618_w22_32:1(a)、9618_s25_33:2(a)）；只用文字解释精度、范围、近似、上溢下溢、改变位数分配的影响 → DR-12。「Calculate … in each of these two systems」→ DR-10，同题组「Explain the problem that occurred」→ DR-12（9618_s23_31:1(a)、1(b)）。
2. **逻辑链五分**：由电路填真值表 → BL-01；由真值表或电路写积之和（不化简）→ BL-04；填卡诺图（含「卡诺图有什么好处」）→ BL-05；圈组、由圈写化简积之和（含「Do not carry out any further simplification」）→ BL-06；用布尔代数或德摩根定律化简、写最简形式 → BL-07。BL-06 小问里另有 1 分「simplest form」→ 加副题型 BL-07（§4）。
3. **文件三分**：记录怎样排列、各组织方式的用途与比较 → DR-06；怎样存取或找一条记录（顺序存取、直接存取、索引）、选存取方式 → DR-07；问散列算法本身、算散列值、冲突是什么及怎样处理 → DR-08。「随机文件怎样直接存取」→ DR-07，有冲突处理得分点加 DR-08（9618_s24_32:7(b)(ii)）。「Describe how records are organised and accessed」→ 按得分点多数（9618_s23_32:2(a) MP1–MP2 讲排列、MP3–MP5 讲存取 → 主题型 DR-07，副题型 DR-06）。
4. **用户定义类型五分**：只用文字说明类型是什么、为什么需要、组合与非组合、挑哪个字段做枚举 → DR-01（9618_s25_33:1(b)）；写枚举或指针声明、把字段改成枚举类型 → DR-02；写 TYPE … ENDTYPE 或改其中一行 → DR-03；声明记录变量或给字段赋值（含赋枚举值）→ DR-04（9618_s22_32:1(b)(iii)）；写 SET OF / DEFINE → DR-05。题干说 set 但 MS 给的是枚举写法 → 按 MS 归 DR-02（9618_s23_31:4(a)）。
5. **TCP/IP 三分**：为什么要协议、协议栈概念、层与层怎样交互、消息怎样经过整个栈、选词填空段落 → CI-01；各层名称、顺序、某层的目的与功能、层与描述连线 → CI-02（题干说「can be viewed as a stack. Complete the diagram」而 MS 只给四层名称 → CI-02，9618_w22_32:3(b)）；具体应用层协议 → CI-03；BitTorrent 单独问 → CI-04。
6. **RPN 三分**：为什么用 RPN、用什么数据结构、用文字描述求值步骤 → SY-10；中缀与 RPN 互转（含转回中缀后代入求值的 1 分）→ SY-11；画栈的变化或求值 → SY-12。
7. **交换三分**：只问电路交换 → CI-05；只问分组交换（含路由器作用、怎样保证完整）→ CI-06；同一小问两种都问 → CI-07。
8. **查找三分**：前提条件、用文字描述二分查找步骤、比较两种方法 → CT-01；写或补全查找代码 → CT-02；性能随数据量的变化、大 O、影响排序性能的因素 → CT-04。「Compare the methods … Refer to Big O」按得分点：方法 Max 3、大 O Max 2 → 主题型 CT-01，副题型 CT-04（9618_s24_32:8(b)）；「Compare the performance … using Big O」→ CT-04（9618_s22_32:8(c)）。
9. **代码里的查找按数据结构定**：见 §3。数组 → CT-02；链表 → CT-08；二叉树 → CT-09；随机文件 → FP-10。
10. **ADT 二分**：列举 ADT、栈的其他用途、栈与队列比较、为何用链表实现栈、用两个栈实现队列 → CT-05；针对某个 ADT 写声明、补全代码、画结点、改指针、改进链表结构（空闲表）→ CT-06 ～ CT-09（9618_w22_32:11(c) → CT-08）。题干把有序二叉树叫「a linked list of nodes … left pointer … right pointer」→ CT-09（9618_w24_31:11(a)、9618_s25_31:4(a)）。
11. **递归三分**：递归是什么、三个基本特征、何时有益、哪些 ADT 可递归实现 → CT-10；为什么用栈实现递归、编译器怎样用栈翻译递归（展开）→ CT-11；追踪递归代码 → CT-12。
12. **OOP 三分**：术语定义、连线或填表、为什么设 PRIVATE、类与对象的区别 → FP-04；补全类图或继承图（方框里的属性与方法签名）→ FP-05（9618_w22_32:10(b)，题干叫「diagram for the object」也算）；写 CLASS … ENDCLASS 或单独一条 PRIVATE 声明 → FP-06（9618_s22_32:1(c)(i)）。
13. **记录与类**：TYPE … ENDTYPE → DR-03；CLASS → FP-06。同一题组里先问记录、再问 PRIVATE：9618_s22_32:1(c)(i) 写 PRIVATE 声明 → FP-06，9618_s22_32:1(c)(ii) 解释为什么设 PRIVATE → FP-04。
14. **Prolog 三分**：写事实 → FP-07；写某目标返回的结果、用变量写查询目标 → FP-08；「Write this as a rule … IF」→ FP-09。
15. **汇编二分**：说寻址方式与 ACC 的值、写出已写好代码运行后的变量值 → FP-02；写代码 → FP-03。P3 的汇编题一律用 FP 题型（考纲 20.1 低级编程），不用 P1 题型。
16. **加密四分**：术语、对称与非对称的区别、加密的理由与种类 → SC-01；用两把密钥发私密消息或已验证消息的步骤（含「Describe the process of asymmetric encryption」）→ SC-02；量子密码 → SC-03；消息先散列成摘要再用私钥加密、接收方比较摘要 → SC-06；证书是什么、怎样获取 → SC-05；证书在数字签名中的作用 → SC-06（9618_s24_31:7(b)）；SSL/TLS 握手（含证书）→ SC-04。
17. **OS 四分**：用户界面怎样隐藏硬件复杂性、OS 怎样最大化资源 → SY-01；多任务、进程状态及其转换 → SY-02；调度的必要性、各调度算法、内核作为中断处理程序、低级调度 → SY-03；虚拟内存、分页、分段、抖动 → SY-04。处理器层面（RISC/CISC、流水线）的中断 → HV-02。
18. **连线、填表、选词填空**：按表中项目属于哪个题型定；跨题型的连线题按条数多数。同一小问的得分点在几个题型间同票时，主题型取题干 / MS 中先出现的那项，其余进 `cross`，标 `low`（D39）。判例：2021 的 9618_s21_31:3(a) OS 术语连线，维持主题型 SY-04，`cross` 为 SY-03、SY-02，信心为 `low`。
19. **机器学习三分**：类别、监督/无监督/强化怎样学习与训练、类别连线 → AI-05（连线里深度学习只占一条 → 仍归 AI-05，9618_s23_31:2(a)）；人工神经网络、深度学习、隐藏层、用途 → AI-06；专门问反向传播或回归 → AI-07。
20. **图与寻路**：图的结构与在 AI 中的用途 → AI-01；A* 与 Dijkstra 的目的、区别、说出一种寻路算法 → AI-02；在图上算 → AI-03（Dijkstra）/ AI-04（A*，表里有 g、h、f）。图作为一种 ADT 列出 → CT-05。
21. **名字相近**：virtual machine → HV-05；virtual memory → SY-04。
22. **翻译程序三分**：解释器怎样执行 → SY-05；编译各阶段 → SY-06；文法（BNF、语法图）→ SY-07 ～ SY-09。判断合法性 → SY-07；写 BNF → SY-08；画语法图 → SY-09。同一小问「画语法图并写 BNF」分成两格时各自归类。

## 8. 得分点拆分规则

### 8.1 哪些行要拆

同时满足下面三条的行写 `markpoints`：

1. `component = 3`；
2. `marks >= 4`；
3. 考生产出的是**伪代码或类图**：主题型属于下表「总是拆」，或属于「作答是代码时拆」且该行的作答确实是伪代码或类图。

| 类别 | 题型 |
|:--|:--|
| 总是拆 | P3-DR-03、P3-DR-05、P3-CT-02、P3-CT-03、P3-CT-06、P3-CT-07、P3-FP-06、P3-FP-10 |
| 作答是代码或类图时拆 | P3-CT-08、P3-CT-09（补全查找、插入代码时拆；画结点图、填指针表不拆）、P3-FP-05（补全类图） |
| 不拆 | 其余题型。特别是：汇编（FP-03）、Prolog（FP-07 ～ FP-09）、BNF 与语法图（SY-08、SY-09）、电路图（BL-03）、计算与填表（浮点、RPN、真值表、卡诺图、Dijkstra、A*、追踪表、变量说明表） |

不拆的理由同 P2 §8.1 的表格题：这些题每一分是一条子句、一条指令或一个格子，没有可复用的编程技能分解，词表里也没有对应标签。

### 8.2 怎样切

P3 的 MS 有两种写法，先认出是哪种：

**A. 有计分清单**（「MP1 … MP7」「One mark for each point: • …」「One mark for TYPE … and ENDTYPE correct」）。范例代码（Example answer / Example algorithm）**不拆**，只用来理解得分点。规则与 P2 §8.2 相同：

1. 一个编号或一个圆点 = 一条 markpoint，`n` 从 1 连续编号。
2. `text` = MS 原文，去掉行首编号（`MP1`、`1`、`•`），跨行用一个空格接起来；其余逐字照抄（含 `…`、`//`、引号的弯直）。校验：`text` 与 `ms_text` 压缩连续空白后，`text` 必须是子串。
3. `marks` 一般为 1。MS 写「One mark for every two correct declarations」这类按数量给分的点，作一条 markpoint，`marks` = 该点能拿的分（总分减去其他点）。例：9618_s24_31:3(b) 共 4 分，「One mark for TYPE FootballClub and ENDTYPE correct」1 分 +「One mark for every two correct declarations」3 分。
4. 得分点总分大于小问分值（MS 写 Max n）→ 写 `ms_max`；相等不写。例：9618_s25_33:12(b) 列 MP1–MP6、Max 4 → `ms_max: 4`。
5. MS 给两套各自独立的计分清单 → 只拆第一套，`tag_note` 写「MS 另有替代计分清单：…」。
6. MS 既有计分清单又给出完整范例（9618_s26_33:10(a)(ii)「Some lines may be left blank」）→ 按 A 拆，不按 B。

**B. 只给完整的范例代码或填空答案片段**，计分说明是「One mark for each correctly completed line」「One mark for each correct line」「One mark for each correctly completed blank」「One mark for any correct row」，或按填空答案计分。这时 MS 里没有逐点文字，得分点要从 QP 的空行找：

1. 渲染 QP 原页（`rows.py render <行 id>`），按从上到下的顺序找出含点线（……）留空的代码行。
2. **一个留空行 = 一条 markpoint**；MS 给完整范例时，`text` = MS 范例代码里对应的那一整行，按 `ms_text` 原样照抄（行内的 `//` 替代写法一起抄；`ms_text` 丢了 ← 的行照 `ms_text` 抄，不自己补）。MS 只给填空答案片段时，按 QP 留空行从上到下逐行对应拆分，`text` 取 MS 片段，不补成整行。例：9618_s22_32:8(a) 的四条为 `INTEGER`、`9 // LENGTH(MyList) - 1`、`Index + 1`、`"Value not found" (or any similar phrase)`（D39）。
3. 计分说明是「per blank」而一行里有两处留空 → 仍作一条 markpoint，`marks` = 该行留空数，`tag_note` 写一句。例：9618_w23_32:12(b) 的 SEEK 一行留空两处（SEEK 与 Location）→ 一条 markpoint、2 分，共 6 条 7 分。
4. 留空行数多于分值（MS 写 Max）→ 写 `ms_max`。
5. QP 留空行在 MS 里找不到对应行（范例写法差得太远）→ 不拆，`tag_note` 写「补全行与 MS 范例对不上，未拆」，这不算低信心。

例：9618_s25_33:11 QP 有 5 处留空（OPENFILE、SEEK、GETRECORD 的变量、PUTRECORD、文件满时的 IF）→ 5 条，`text` 分别是 `OPENFILE "StockList.dat" FOR RANDOM`、`SEEK "StockList.dat", Location`、`GETRECORD "StockList.dat", CurrentStock`、`PUTRECORD "StockList.dat", NewStock`、`IF Stored = FALSE THEN`。

### 8.3 怎样打技能标签

每条 markpoint 打 **1–3 个**标签，取「拿不到这一分最可能是因为不会哪项技能」。只用 `papers/p2/skill_tags.json` 里的标签与 §8.4 的提议标签。P2 指南 §8.3 的对照表照样适用；P3 常见写法补充如下：

| MS 写法或留空行内容 | 标签 |
|:--|:--|
| TYPE … and ENDTYPE correct / Declare used correctly for every field | `record-type` |
| DECLARE … as STRING / DATE；… fields correct (shaded) | `data-types`（讲 DECLARE 用法时加 `record-type`） |
| 字段类型用题目定义的枚举类型；TYPE … = SET OF …；DEFINE … (…) : … | `user-defined-type`（提议） |
| OPENFILE … FOR RANDOM；SEEK；GETRECORD；PUTRECORD | `random-file`（提议） |
| OPENFILE … FOR READ / WRITE；WHILE NOT EOF；READFILE；WRITEFILE；CLOSEFILE | `file-open-read`、`loop-to-eof`、`file-write`、`file-close` |
| Found ← FALSE / Stored ← FALSE（循环前赋初值） | `initialise-variables` + `flag-variable` |
| WHILE Found = FALSE AND NotInList = FALSE / WHILE NOT Stored AND Location <= Max | `pre-condition-loop` + `logic-ops`（查找时加 `binary-search` 或 `linear-search`） |
| Mid ← (Low + High) DIV 2；TopOfList ← CurrentItem + 1；NotInList ← TRUE | `binary-search`（DIV 单独成点时加 `div-mod`） |
| IF ToFind = Names[CurrentItem] / Check if … > Value | `relational-ops`（+ 所在算法的标签） |
| Temporary assignment of the element being ‘inserted’ / Moving data to adjacent element / Re-insertion | `insertion-sort`（取出加 `assign-value`，后移加 `shift-values`） |
| Swap / NoSwap / reduce boundary | `bubble-sort` |
| IF Top < Max – 1 / IF Length > 0；Top ← Top + 1；RETURN Item | `stack-array` 或 `queue-array`（返回加 `return-value`） |
| Pointer ← NextPointer[Pointer] / WHILE Pointer <> 0 | `linked-list` |
| NowPtr ← BinTree[NowPtr].LeftPtr / RootPtr | `binary-tree`（记录数组点号访问加 `array-of-records`） |
| FUNCTION … RETURNS INTEGER / PROCEDURE Push(NewData : STRING) | `module-header` |
| CLASS … ENDCLASS；PUBLIC PROCEDURE NEW(…) | `class-definition` |
| PRIVATE … : STRING；attributes available only through methods | `encapsulation`（类型要求加 `data-types`） |
| SetX(…) / GetX() seen | `getter-setter` |
| INHERITS / 调用父类构造 | `inheritance` |
| Push(…) / CALL … / 使用 Pop() 的返回值 | `procedure-call` |
| INPUT …（提示语已给出时也用它）；OUTPUT … message | `input-prompt`；`output-format` |

不要给 P3 得分点打 `translate-pseudocode`、`exception-handling`、`p4-identifiers`。

## 10. 设计说明与试标

- **章节**：按考纲第 13–20 节建章，章码采用任务卡建议，另把 15.2 布尔代数与逻辑电路从 HV 拆出成 **BL 章**（共 9 章）。理由同 P1 的 D15：每卷必考（每卷 8–12 分），套路是一步步的计算（真值表 → 积之和 → 卡诺图 → 化简），与 HV 的描述题完全不同，单独成章便于学习与统计。BL 不与 P1 的 LG 冲突（P1、P2 章码：IR CM HW LG PF SS SP EO DB / AD DT PG SD）。章内顺序就是学习顺序（概念 → 计算或读代码 → 写代码）。
- **粒度**：一个题型 = 识别信号、作答套路、MS 得分句模式都稳定的一种考法。核验语料（2022–26s，去掉 `equivalent_of` 与 §6 的逐字重复后约 560 行）中少于 2 次的考法已并入近邻：路由器并入 CI-06，内核与低级调度并入 SY-03，用两个栈实现队列并入 CT-05，RISC/CISC 中断处理与流水线合为 HV-02，卡诺图的好处并入 BL-05。因考纲有独立要求而保留的少数题型：P3-SY-05（核验 1 次）、P3-FP-01（核验 0 次，只在 2021 扩展卷），以及恰好 2 次的 DR-05、CI-04、HV-04、BL-02、BL-03、SY-01、AI-04、AI-07、CT-03、CT-11。
- **写代码题**：P3 的代码题几乎都是「一个结构一个题型」，按数据存在哪里归类（§3），不需要 P2 的优先级表。
- **试标**：`papers/p3/pilot_tags.csv`（列 `id,primary,cross,confidence,note`，多个副题型用 `;` 分隔），3 份不同考季、不同 variant 的卷全部小问（9618_w22_32、9618_s24_31、9618_s25_33，共 81 行，225 分）。每行都找到了主题型；低信心 0 行；带副题型 1 行；用到 49 个题型。`papers/p3/pilot_markpoints.jsonl`（每行 `{"id", "ms_max", "markpoints"}`，`ms_max` 为 null 表示不写该字段）：7 行需拆分的小问拆出 31 条得分点，用到 19 个技能标签（含 2 个提议标签）；每条 `text` 已核对为 MS 原文子串（压缩空白后），每行得分点总分等于分值或带 `ms_max`。
- **试标中补充的规则**：① 9618_w22_32:11(c)「怎样改进链表」原放 CT-05，改为 CT-08（空闲表属链表实现）；② 9618_s24_31:10(b)、9618_s25_33:11、9618_w22_32:11(b) 的 MS 只给完整范例代码，由此定出 §8.2 B「按 QP 留空行拆」；③ 9618_s24_31:3(b)「每两个声明一分」定出 §8.2 A 第 3 条；④ 9618_s24_31:4(b) 定出文件存取与组织方式的副题型规则；⑤ 9618_s24_31:8(c) 的 Prolog 规则 4 个得分点都是同一技能，定为不拆。

## 11. 考纲变化核对（2027–2029）

- **对照了什么**：`sources/official/9618_syllabus_2027-2029.pdf` 第 13–20 节与 `sources/official/support/9618_Computer_Science_2026_Syllabus_Document.pdf` 同节逐行比对，内容完全相同（只有排版空白不同）；2027–29 考纲更新说明只涉及「各级别考哪些卷」与计算器的说明，没有 A Level 内容变化。2027–29 伪代码指南的用户定义类型（枚举、指针、集合 SET OF / DEFINE、记录）、随机文件（SEEK / GETRECORD / PUTRECORD）、OOP（CLASS、PRIVATE、NEW、INHERITS）写法与 2026 版、2023–25 版一致。
- **结论**：语料（2021–2026s）里的每一种考法都在 2027–29 考纲之内，没有题型需要标「不再考」。2021–25 年使用的旧版考纲原件不在 `sources/` 里，无法逐条比对；P3 语料中未见超出现行考纲的考法。
- **考纲有、语料尚未考过**（在相应题型 `summary` 里注明）：JK 触发器与触发器真值表（BL-03）；字典 ADT（CT-05）；写递归算法（CT-12）；页面置换（SY-04）；在 P3 写异常处理代码（FP-11，属 P4）。考纲 18.1 明确不要求写建图或搜索图的算法（AI-01）。

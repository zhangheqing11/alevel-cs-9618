## 书末　跨章入口、整题得分链与证据文档 {#back}

一道 P4 大题会跨好几章。先看当前小问要你交哪一格，再看数据与操作；下面的入口帮助你找卡，不能替代该题自己的 QP、MS 和证据模板。

**遇到混合小问时**：先认模块身份。Push/Pop 本身属于 SQ；链表/树操作属于 LT；排序/二分属于 SR；类的构造/重写属于 OP。其余普通模块再看承担主要得分点的结构，同分按 tagging-guide 的优先级。不要只凭故事、函数名或 main 两个词判型。

例如 ⟦9618_s23_42:3(e)(i)⟧ 按顺序遍历员工数组，用 getter 输出员工号与总工资，主题型是 AR-04；⟦9618_s23_41:2(d)(i)⟧ 主要创建对象和调用方法，才是 OP-07。递归二分仍是 SR-02；用类实现树插入仍是 LT-03。

### 一道大题的典型得分链

用 ⟦9618_s25_43:1(a)⟧ 至 ⟦9618_s25_43:1(e)(ii)⟧ 串一次：程序从 QueueData.txt 读整数进线性队列，再用 Dequeue 逐个取数求和。完整 Python 在 SQ-02 卡。整题 QP p.2–3；MS p.7–18。

| 环节 | 本题做什么 | 本题 MS 原句举例 | 怎样核对 |
|:--|:--|:--|:--|
| 声明与初值（SQ-02） | 50 格 INTEGER 数组、全 -1，两个全局指针 -1 | 「(Global) Queue array with 50 integer elements …」⟦9618_s25_43:1(a)⟧ | 真有 50 格，类型、全局位置与初值都对 |
| ADT 操作（SQ-02） | Enqueue 判满、存值、更新尾指针与首次入队的头指针；Dequeue 判空并先取后移 | 「Accessing and returning element at Queue[HeadPointer] (before HeadPointer is incremented)」⟦9618_s25_43:1(c)⟧ | 指针约定照 QP；空值 -1 与后续处理一致 |
| 读文件（FL-01） | CreateQueue 读到 EOF，每项去换行、转 INTEGER、交给 Enqueue | 「… calling Enqueue() once with each value …」⟦9618_s25_43:1(d)⟧ | 不多调一次，不直接绕过 Enqueue 写数组 |
| 文件失败路径（FL-01） | 文件访问放 try 中，有适当错误输出 | 「Exception try, catch with appropriate output. All file access within try」⟦9618_s25_43:1(d)⟧ | 文件缺失也能处理，正常路径适当关闭文件 |
| 主程序处理（SQ-04） | 调 CreateQueue；反复 Dequeue，返回 -1 停，累加并输出 | 「… repeatedly until return value is –1」⟦9618_s25_43:1(e)(i)⟧ | 保存每次返回值；只在有效数据上累加；虽然写在 main，仍归 SQ-04 |
| 截图（MP-03） | 用原题文件运行，显示合计 | 「1 mark for screenshot showing 3059」⟦9618_s25_43:1(e)(ii)⟧ | 必须拍到实际结果 3059，不能用“没有报错”代替 |

这条链的每一环都有自己的分，不要等整题全部完成才保存代码和填写证据。即使某一模块还没写完，也先把已完成的声明、模块头、调用语句按题号放进对应格；不能把未运行的部分写成已通过测试。

### 证据文档怎样交

以本题官方 `9618_s25_sf_43/evidence.doc` 及 QP 说明为例：

1. 开始时填写页眉的姓名、centre number、candidate number；按本卷要求保存成 `evidence_<centre number>_<candidate number>`，保留所用文档格式。程序另按 QP 要求保存，例如 Question1_J25、Question3_J25。
2. 一格一个题号。标着 program code listing 的格放对应代码；标着 screenshot 的格放真实运行截图。本题模板把 1(a)、1(b)、1(c)、1(d)、1(e)(i) 分成五个代码格，1(e)(ii) 是截图格。
3. 代码保留缩进、模块头、属性/数组的类型与大小注释；类图声明题只交题目要求的部分。修改代码后，用当前保存版本更新相应格。
4. 截图要能读清本格要求的数据。需要输入过程的保留输入，需要 before/after 的保留两组结果；若一张放不下，用清晰的连续多张，避免为了塞进一张而缩小到读不清。
5. 文件内容截图按该题要求处理。⟦9618_s25_41:2(e)(ii)⟧ 要先看见提示与输入 TheData.txt，再看见红色数字文件的内容，文件名与内容必须同图（QP p.5；MS p.29）。控制台里 print 相同数据不能代替真实文件的画面。
6. 定期保存证据文档与程序。官方 evidence 模板举例每 10 分钟保存一次；结束前逐格查题号、清晰度、缺项以及代码与截图是否来自同一最新版本。

学习时可以先用程序输出核对行为，再按证据格清单人工核对；练习测试通过仍需要检查类型注释、模块结构等人工项。s26 专项刷题与复测跳过，保留给限时整卷；手册得分地图的计数仍包含 s26（D1、D44）。

### P4 命令词与 MS 常用语

| 题干/清单用语 | 要做什么 | 本题依据与限制 |
|:--|:--|:--|
| Write program code to declare… | 写真实声明/初始化，不只写说明文字 | ⟦9618_s23_41:2(a)(i)⟧ 的类头、私有属性/类型、构造、参数赋值、初值各有分 |
| Use your programming language's appropriate constructor | Python 用 __init__，参数与类图一致 | ⟦9618_s23_41:2(b)(i)⟧，别另写一个普通 Constructor 方法 |
| Write … get methods | 返回属性给调用者 | ⟦9618_s23_41:2(a)(ii)⟧，不能 print 替代 return |
| Write … main program / Amend / Edit | 把新调用放入当前流程，保留先前要求 | ⟦9618_s23_42:2(f)(i)⟧ 的六次输入→出队→重试→输出顺序 |
| Test … in the order given | 使用指定值与顺序实际运行 | ⟦9618_s22_42:1(d)(ii)⟧ 的 11–21，不自行删掉第十一次失败尝试 |
| Copy and paste program code / screenshot | 按证据格交相应代码或截图 | ⟦9618_s25_43:3(c)(i)⟧ 与 ⟦9618_s25_43:3(c)(ii)⟧ 分别是代码与输出证据 |
| (and end where appropriate) | 模块头要与正确作用域配套；Python 用缩进收束 | ⟦9618_s25_43:1(b)⟧，不在 Python 添加 ENDFUNCTION |
| … / continuation | 看是否是另一个独立点，不能自行合并或拆分 | ⟦9618_s25_41:1(c)⟧ 语料 MP2/MP3 同在 MS 第二个圆点内，按独立动作拆（D43） |
| `//` / alternative wording | 同一点的替代说法，不重复计分 | ⟦9618_s23_41:2(c)⟧ 可按对象类型判断或重写输出等，只算该点 |
| 1 mark each to max n | 满足的独立点累加，最多 n 分 | ⟦9618_s23_42:2(f)(i)⟧ 五点 Max4；不要称五分 |
| suitable / appropriate message | 提示要能说明本题结果，不要求臆造唯一句子 | ⟦9618_s22_42:1(d)(i)⟧；题目点名 Full/Stored 等则按该题文字来 |

语料 `markpoints[].n` 是拆分后的连续编号，不保证等于 MS 印刷编号。例如 s25_41:1(c) 的 MP2/MP3 来自同一圆点；对照时既看独立动作，也看总分与 Max。给分只认这道小问自己的 MS；ER 用来理解容易错在哪里，不能增加或放宽得分条件。
